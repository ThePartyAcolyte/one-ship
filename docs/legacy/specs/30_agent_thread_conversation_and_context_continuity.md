# Spec 30: Agent Thread, Conversation & Runner-Neutral Context Continuity
**Document Version:** 0.3.0  
**Status:** IMPLEMENTED (Phases A–E completed 2026-10-08..09; F6 multi-agent keyring test tracked in `TECHNICAL_DEBT.md` #23).  
**Domain:** Chat continuity, conversation lifecycle, multi-runner context handoff, conversation restoration  
**Related:** Spec 22 (session lifecycle, journal), Spec 16 (snapshots), Spec 17 (accounts), Spec 12 §6 (caller identity)

---

## 1. Motivation

The conversation model was designed when Antigravity (`agy`) was the only runner. Continuity was obtained by re-attaching the runner's own session (`agy --conversation <id>`), which let the user change account or model while keeping context. With OpenCode and Claude Code that mechanism no longer generalizes:

1. Runner sessions are runner-specific and cannot be replayed into another runner.
2. Changing runner currently **archives** the active conversation and starts clean, silently dropping context (audit F1).
3. Every spawn sends the persona prompt and obliges the model to answer a greeting: one billable model turn per start, before the user has said anything (audit F2).
4. A single `agy_conversation_id` column stands in for "the native session" of every runner (audit F4).
5. There is no way to say "let's pick up the database topic again" and have the system find and restore that conversation (audit F9).

The user-facing chat is one continuous stream per agent. The software-level unit that matters to a runner is a bounded working cycle. This spec separates the two and defines how context travels between runners and across time.

## 2. Terminology (APPROVED 2026-10-08)

| Term | Meaning | Current implementation |
|---|---|---|
| **Thread** | The continuous, never-ending relationship with one agent persona in one project; what the user sees as "the chat". Like a contact in an address book. | Implicit: all `agent_chat_turns` of `(project_id, agent)` shown as one stream |
| **Conversation** | A bounded working cycle inside a Thread: opens with a clean context, has a topic, and ends by resolution, closure or context clean. A Thread contains many Conversations in sequence. | `agent_conversations` (`topic`, `status`) |
| **Native Session** | The runner-level context of one process lifetime or resumable session (`agy` conversation id, OpenCode ACP session id, Claude Code session id). A Conversation owns an ordered list of Native Sessions: it gains a new one whenever the runner changes or a session cannot be resumed. | Single column `agy_conversation_id` |
| **Brief** | The portable context package ONE-SHIP assembles to seed a new Native Session of any runner (§5). | Does not exist; only a UI-built markdown handoff |
| **Minutes** | Structured record of a Conversation written by the agent: summary, decisions, files touched, debt. | `agent_session_journal` ("session minutes") |
| **Persona Preamble** | The persona system prompt plus assigned skills, prepended to the first user message of a Native Session that has no history. | Sent at spawn by `build_agent_initial_prompt` |
| **Readiness Stub** | A synthetic `system` turn ("Agent ready") inserted by ONE-SHIP when a Conversation opens. Never generated by a model; gives the Thread a visible beginning. | The model's greeting turn |
| **Resume** | Re-attach the same Native Session (same runner, session still valid). | `--conversation`, ACP `session/load` |
| **Reopen** | Start a new Native Session seeded with a Brief built from a past Conversation, on any runner. | Does not exist |

Rule: the bare word "session" in code and docs means **Native Session** only. "Conversation" never means a runner-native identifier; those are always `native_session_id`.

```text
Thread (project × persona) ── continuous chat stream
 ├─ Conversation #1  "database schema"        closed
 │   ├─ Native Session A (agy)     ─ switched runner ─┐
 │   └─ Native Session B (claude)  ◄── Brief ─────────┘
 ├─ Conversation #2  "ui polish"              closed
 └─ Conversation #3  "database indexes"       active  ◄── Reopen(#1) seeded Native Session C
```

## 3. Target Data Model

All durations use `_ms`, counts `_count` (AGENTS.md §8).

**`agent_conversations`** (extend)
- `summary` TEXT NULL — agent-authored summary of the Conversation (§6).
- `closed_at_ms` INTEGER NULL, `close_reason` TEXT NULL (`resolved` | `cleaned` | `superseded` | `runner_unavailable`).
- `persona_preamble_pending` INTEGER NOT NULL — 1 until the Preamble has been delivered to the current Native Session.
- `runner`, `model`, `effort`, `account_id` become **overrides**: NULL means "inherit from the persona" (§7). The `DEFAULT 'agy'` is removed.

**`conversation_native_sessions`** (new)

| Column | Meaning |
|---|---|
| `id` | primary key |
| `conversation_id` | FK `agent_conversations.id` |
| `runner`, `model`, `account_id` | configuration the session ran with |
| `native_session_id` | runner identifier, NULL until the runner reports it |
| `started_at_ms`, `ended_at_ms`, `end_reason` | lifecycle (`exit` \| `runner_switch` \| `invalidated` \| `cleaned`) |
| `seeded_from_brief` | 1 if started from a Brief rather than a resume |

**`agent_chat_turns`** gains `native_session_row_id` so each turn records which Native Session produced it.

**`agent_session_journal`** (Minutes) is re-keyed to `conversation_id` (ONE-SHIP id); `agy_conversation_id` is kept only as a native reference.

## 4. Lifecycle

```text
open Conversation ──► Readiness Stub (synthetic turn, no model call)
        │               process spawned idle; nothing sent to the model
        ▼
first user message ──► prompt = [Persona Preamble] + [Brief if Reopen / runner switch] + user text
        │               persona_preamble_pending := 0
        ▼
 working … (Resume on restart when runner unchanged)
        │
        ├─ runner switch ─► close Conversation (superseded), open a new clean one (no automatic Brief)
        ├─ clean context ─► close Conversation (cleaned), open a new one   ← most common closure
        └─ resolution ───► agent records Minutes + summary → close Conversation (resolved)
```

**Opening the chat** resumes the last active Conversation when the runner is unchanged. If the runner changed, a new clean Conversation starts. Context from an earlier Conversation travels only by explicit **Reopen** (or an explicit context transfer), which seeds a Brief.

**Closure** is mainly a user action (the user decides a topic is finished and cleans the context). The agent may also close a Conversation (recording Minutes and a summary). Detecting that the user has moved to a new topic and proposing a clean context is agent behavior, delivered as a skill, not platform logic.

- **Spawn is silent.** The process starts idle; the UI shows process status. The only artifact of "arrival" is the Readiness Stub.
- **Persona Preamble** is delivered exactly once per Native Session that lacks history, together with the first user message. Resumed sessions never receive it again. Editing a persona therefore takes effect on the next Native Session without history.
- **Hybrid resume rule:** if the runner is unchanged and the Native Session is still valid, Resume it (cheaper, keeps tool state). If the runner changes, the Conversation is closed as `superseded` (never silently archived with its context lost) and a new clean Conversation starts. A Brief is applied only through Reopen or an explicit context transfer. A Conversation therefore spans several Native Sessions only when a session becomes invalid on the same runner and is re-seeded.
- The Thread's visual continuity is unchanged: Conversations appear as separators in the single stream.

## 5. The Brief

A Brief is built by ONE-SHIP at the moment a new Native Session needs context. It is plain text, runner-neutral, and never requires a model call.

Contents, in priority order, each bounded:
1. **Summary** of the Conversation if present (`agent_conversations.summary`). If absent, omitted.
2. **Recent turns:** the last `brief_recent_turns_count` turns of the Conversation (dialogue and artifact references, not full artifact bodies).
3. **Minutes digest:** decisions and tags from the Conversation's Minutes.
4. **State report:** files touched (from snapshots/Minutes), technical-debt items recorded and TODOs created/resolved during the Conversation.
5. **Open items:** pending approvals and unresolved delegations.

Limits: `brief_recent_turns_count` (default 20) and `brief_max_bytes` (default 32768), both registered in `get_all_plugin_schemas()` (AGENTS.md §11.1). When over budget, drop in reverse priority order; the Summary and the last turns are dropped last.

A Brief is *context*, not a replay: tool state and file reads of the original Native Session are not reconstructed, and the agent is told so in the Brief header.

---

## 6. Summary Authorship

The summary is written by the agent as part of its normal flow, never by an extra background process. `record_session_minutes` gains a `conversation_summary` field and, when the Conversation closes, a final call fills `summary`. If an agent never writes one, the Brief falls back to recent turns plus the Minutes digest. No hidden model call is made on the user's behalf.

---

## 7. Configuration Precedence

For `runner`, `model`, `effort`, `account_id` at launch:
1. Explicit value in the launch request (user chose it in the chat selector).
2. Conversation override (non-NULL).
3. Persona declaration (`rula.toml`).
4. Project/global defaults, then runner schema baseline.

Selecting a value in the chat selector writes the Conversation override. Editing the persona writes the persona only; a Conversation without override inherits it. Because overrides are NULL by default, a persona change is visible immediately and nothing is silently pinned to `agy`.

The `claude` runner authenticates with the CLI's own login: an `account_id` selected for it is informational and must be shown as such.

---

## 8. Restoring Past Conversations

Agents and the user need to find and reopen earlier work ("let's resume the database topic").

- **Search:** `search_conversations(query, status?)` over `topic`, `summary`, Minutes and tags. Phase 1 is lexical (SQLite FTS5); semantic indexing is the transversal service planned in Spec 22 and plugs into the same tool.
- **Reopen:** `reopen_conversation(conversation_id)` closes nothing in the old Conversation, opens a new active Conversation in the same Thread linked by `reopened_from`, and seeds a new Native Session with that Conversation's Brief. For the user it appears as the Thread continuing.
- Both tools resolve the calling agent and project from the attested `CallerContext` (Spec 12 §6); no identity parameters.
- UI: a "Reopen" action on a Conversation separator and a search field in the Thread.

### Phase B as built (differences from §3–§7)
- **Schema reset, no migration (D7).** `PRAGMA user_version` gates the conversation schema (`CONVERSATION_SCHEMA_VERSION = 1`). On an older database `init_database` copies the whole database to `oneship.pre-spec30-<epoch>.db` (`VACUUM INTO`), drops `agent_session_metrics`, `agent_chat_turns`, `conversation_native_sessions` and `agent_conversations`, and recreates them. Chat history is therefore reset once; the backup keeps the old rows.
- **`agent_conversations`**: `runner`, `model`, `account_id`, `effort` are nullable overrides; `closed_at_ms` and `close_reason` (`resolved` | `cleaned` | `superseded`) added; `agy_conversation_id` removed (the record exposes `native_session_id`, the latest id reported among the Conversation's Native Sessions). `summary` is left to Phase D. Archiving through a topic switch does not set the close fields; only a closure does.
- **`conversation_native_sessions`** created as specified (`seeded_from_brief` exists but is unused until Phase C). A row is opened by `launch_agent` before the process spawns (ended with `exit` if the spawn fails) and by `restart_agent_with_session`; agents spawned elsewhere (initializer, flag resolvers) get one when they report a session id. A session is ended when the next one opens (`exit`) or when its Conversation closes (`runner_switch` for `superseded`, `cleaned`), not at process exit.
- **`agent_chat_turns.native_session_row_id`** records the open Native Session at insert time.
- **Persona Preamble decision (audit F15).** A launch injects the Preamble whenever there is nothing to resume (`session_resume_id` is None), so a runner without native resume (today `claude`) receives the persona again after a relaunch.
- **Precedence (§7)** is implemented in `conversation::apply_conversation_config`, used by the chat selector and by `launch_agent` when explicit arguments are given. A value equal to the persona's, with no override present, is not stored, so a later persona edit still applies.
- **Runner change** (`apply_conversation_config`): the active Conversation is closed as `superseded` and a new one (topic "General Workspace") is created with the new overrides. `db_get_active_agent_session` no longer archives anything; it only returns a resumable Native Session of the same runner.
- Clean context (`launch_agent` with `clean_context`) opens a new Conversation that keeps the overrides in force.

### Phase D as built (differences from §11 plan)
- **No schema-version bump and no wipe.** The journal holds 21 real devlog entries across 5 projects, which D7 (wipe of *conversation* data) did not cover. `agent_conversations.summary` is added with `ensure_column`; `agent_session_journal` is rebuilt once in a transaction (`migrate_journal_to_conversation_key`): rows are kept with `conversation_id = NULL`, `agy_conversation_id` becomes nullable. Idempotent; covered by a temp-DB test.
- **`record_session_minutes`** takes no identifier: the Conversation is the caller's active one (`db_get_or_create_active_conversation`), `agy_conversation_id` is the Conversation's latest Native Session id (reference only), and `conversation_summary` (optional) is written with `db_set_conversation_summary`. The `sess-<project>-<agent>` fallback id and the `find_agy_session_for_agent` heuristic were removed. `oneship-devlog` explains the summary; Spec 22 updated.
- **Not re-keyed:** `agent_session_metrics` already carries `conversation_id` and its `agy_conversation_id` primary key serves the statusline, so it stays. Snapshots remain keyed by the native id (milestone snapshots use it, falling back to the Conversation id) — audit F11 stays open.
- **UI:** `SessionJournalItem` gets `conversation_id` and a nullable `agy_conversation_id`; the Devlog "Resume" button appears only for Minutes that have a native id (replaced by Reopen in Phase E).

### Phase C as built
- **`src-tauri/src/brief.rs`:** `compose_brief` (pure, unit-tested: ordering, latest-turn selection, drop order, hard byte cap, UTF-8 boundaries) and `build_brief(conversation_id)` (reads SQLite, no model call). `BriefError` is a `thiserror` enum. Sections: header (context-not-replay notice), Summary, recent turns (artifacts referenced, never embedded; each turn limited to an even share of the budget), `BriefStateReport` (snapshots, TODOs, technical debt), `BriefOpenItems` (approvals, delegations), and Minutes digest. Drop order: Minutes digest → oldest turns → summary truncation → header truncation; the result lists `dropped_sections`.
- **Config:** `supervisor.brief_recent_turns_count` (20) and `supervisor.brief_max_bytes` (32768) registered in `get_all_plugin_schemas()`; `SettingsModal` renders them generically.
- **Hybrid resume (`launch_agent`):** when there is no native session to resume, the agent is not the initializer, and the Conversation has user/agent turns, the Brief is built *before* spawning (a failure aborts the launch and ends the Native Session) and travels as `persona preamble + "---" + Brief` in `pending_preamble`; the Native Session is marked `seeded_from_brief`. A clean context or a runner change creates a new Conversation, which has no turns and therefore no Brief (D5).
- **Context transfer:** `ContextTransferModal` calls the daemon command `build_conversation_brief({ projectPath, agentId })` (the source agent's active Conversation), previews the backend text, appends the user's notes and sends it as the first user message to the destination agent. The markdown assembled in the UI, its Minutes/turn toggles and the `recentMessages`/`sessionJournals` props were deleted (audit F8).

### Phase E as built
- **Search:** FTS5 table `conversation_search` (one row per Conversation: topic + summary + Minutes title/summary/decisions/tags), rewritten by `reindex_conversation` on conversation creation, summary update and Minutes insert, and backfilled at startup when empty. User text is quoted word by word and OR-ed, ranked by relevance (`fts_query_from_text`); an empty query is an error. Results are scoped to the caller's project and agent and bounded by `supervisor.search_conversations_max_results_count` (10). Conversation *turns* are not indexed; a Conversation with no summary or Minutes is findable only by topic.
- **Reopen:** `db_reopen_conversation` validates the source (same project and agent, not the active one), closes the current Conversation as `cleaned`, creates a new one with the source's topic and the *current* Conversation's overrides, and sets `reopened_from`. `conversation::reopen_conversation` additionally builds the source's Brief and, when a process is live, opens a seeded Native Session that carries the live session's native id.
- **Delivery of the Brief:** MCP path → returned as the tool result (the agent is already running). UI path (daemon command `reopen_conversation`) → queued on the live process (`queue_context_for_next_input`, rides the next input after any pending Preamble); a stopped agent is seeded by `launch_agent` through `reopened_from` while the reopened Conversation has no dialogue of its own. Once it has dialogue it is briefed from itself, so the source's summary is no longer included (known limitation).
- **Removed (F10):** MCP tool `resume_agent_session`, `resume_agent_session_cmd`, `restart_agent_with_session`, the high-context resumption modal and `startCleanSessionWithMilestone`, and the stream separators keyed by `agy_conversation_id`. Separators now key on `conversation_id` and offer `Reopen` for the Conversation above them; the Devlog view offers `Reopen` for Minutes that have a `conversation_id`.
- **UI:** `ConversationSearchModal.vue` (header search button of the chat overlay). `oneship-devlog` documents the tools, the summary and the topic-change suggestion (D4).
- **Tests:** scoped/ranked/filtered search and query quoting on temporary databases.

## 12. F6 — Account Isolation (PROPOSAL — awaiting approval)

**Problem (verified in code):** `agy` reads one OS keyring entry (`secret-tool … service gemini username antigravity`). `launch_agent` rewrites that entry under `keyring_lock()` before every `agy` spawn and then calls `db_set_active_account`, and `switch_account` does the same. The "active" flag therefore follows the last spawn instead of any per-agent choice. **Correction (maintainer, 2026-10-08):** an earlier draft stated that two concurrent `agy` agents cannot hold different accounts. That was an inference, not an observation. The maintainer's recollection is that a running `agy` authenticates at startup, refreshes its own tokens and keeps that identity while another `agy` is launched with a different account. That is consistent with the spawn-time lock in `launch_agent`, and it is **unverified either way**. If it holds, per-agent accounts already work and the keyring is only a hand-off at spawn; the remaining defects are the misleading "active" flag and a possible token-refresh write-back from an older process overwriting the entry.

**Verification needed before any design:** launch agent A with account X, then agent B with account Y, and confirm from the server-side identity (e.g. each process's reported account/quota) that A keeps X while both run, including after A refreshes its token.

**Options**
| Option | What changes | Pros | Cons |
|---|---|---|---|
| 1. Honest global model (recommended first step) | Remove `db_set_active_account` from spawn (the keyring watcher and `switch_account` own the flag). `launch_agent` refuses an `agy` launch whose resolved account differs from the account of an already-running `agy` agent, with a typed error naming the conflict. The chat selector shows the account as "shared by all agy agents". | Small, no new infra, removes the flag flip and the silent overwrite of a running agent's account | Does not allow concurrent distinct accounts |
| 2. Per-agent isolated credential store | Spawn each `agy` with a private keyring (e.g. `dbus-run-session` + dedicated `gnome-keyring-daemon`, or per-agent `HOME`) | True per-conversation accounts | Needs a spike to prove `agy` honors it; extra daemons; breaks the shared OAuth login flow (`initiate_add_account`) |
| 3. Status quo with documentation | None | None | Leaves F6 open |

**Note:** the Options below assume the unverified premise that concurrent accounts are impossible. If the verification above shows they work, Option 1 reduces to "stop flipping the active flag on spawn", its conflict check is dropped, and Option 2 is unnecessary.

**Proposed work:** implement Option 1 now (Rust: `supervisor.rs` spawn block, `accounts.rs`; frontend: selector label and error surfacing in `dialogueStore.ts`; Spec 17 updated), and run a time-boxed spike for Option 2 only if concurrent distinct accounts are required.

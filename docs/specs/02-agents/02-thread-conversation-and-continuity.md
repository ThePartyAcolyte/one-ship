# Thread, Conversation, and Runner-Neutral Context Continuity

## Purpose

Separate the continuous user-facing chat relationship with an agent persona (**Thread**) from the bounded working cycle (**Conversation**) and the underlying CLI runtime context (**Native Session**). Define how ONE-SHIP persists conversations, builds runner-neutral **Briefs** without model calls, switches runners cleanly, indexes and reopens past topics, and resolves execution configuration precedence.

## Scope

In scope: ubiquitous conversation terminology, SQLite tables (`agent_conversations`, `conversation_native_sessions`, `agent_chat_turns`, `agent_session_journal`, `conversation_search` FTS5), silent spawn and Readiness Stubs, Persona Preamble delivery, `src-tauri/src/brief.rs` Brief construction, `src-tauri/src/conversation.rs` lifecycle and overrides, `search_conversations` / `reopen_conversation` (MCP + daemon commands), and frontend modals (`ConversationSearchModal.vue`, `ContextTransferModal.vue`).

Out of scope: process spawning and stream protocols (see [Native Process Supervisor](01-native-process-supervisor.md)), `post_agent_response` / `request_approval` (see [MCP Dialogue Channel and Chat Overlay](03-mcp-dialogue-and-chat-overlay.md)), and multi-account credential swapping (see [Multi-Account Management](04-multi-account-management.md)).

## Model / Design

### 1. Terminology

| Term | Meaning | Implementation |
| :--- | :--- | :--- |
| **Thread** | The continuous, never-ending relationship with one agent persona in one project; what the user sees as "the chat" (like a contact in an address book). | All `agent_chat_turns` of `(project_id, agent)` rendered as one stream |
| **Conversation** | A bounded working cycle inside a Thread: opens with clean context, has a topic, and closes by resolution, context clean, or supersession. A Thread contains many Conversations in sequence. | `agent_conversations` (`topic`, `status`, `summary`, `closed_at_ms`, `close_reason`, `reopened_from`) |
| **Native Session** | The runner-level context of one process lifetime or resumable session (`agy` conversation ID, OpenCode ACP session ID, Claude Code session ID). | `conversation_native_sessions` (`native_session_id`) |
| **Brief** | Plain-text, runner-neutral context package assembled by ONE-SHIP from SQLite to seed a new Native Session without a model call. | `src-tauri/src/brief.rs` (`build_brief`, `compose_brief`) |
| **Minutes** | Structured record of a Conversation authored by the agent: summary, decisions, files touched, debt. | `agent_session_journal` |
| **Persona Preamble** | Persona system prompt plus assigned domain skills, prepended to the first user message of a Native Session lacking history. | `ManagedProcess.pending_preamble` |
| **Readiness Stub** | Synthetic `system` turn (`"Agent ready"`) inserted by ONE-SHIP when a Conversation opens. Never generated by a model. | `system` turn on Conversation open |
| **Resume** | Re-attach the same Native Session (same runner, session still valid). | `agy --conversation`, OpenCode `session/load`, Claude `--resume` |
| **Reopen** | Start a new Native Session seeded with a Brief built from a past Conversation, on any runner. | `reopen_conversation` (MCP & daemon command) |

**Naming invariant:** In code and documentation, the bare word "session" means **Native Session** only; runner-native identifiers are always named `native_session_id`.

```text
Thread (project × persona) ── continuous chat stream
 ├─ Conversation #1  "database schema"        closed
 │   ├─ Native Session A (agy)     ─ switched runner ─┐
 │   └─ Native Session B (claude)  ◄── Brief ─────────┘ (explicit Reopen / transfer)
 ├─ Conversation #2  "ui polish"              closed
 └─ Conversation #3  "database indexes"       active  ◄── Reopen(#1) seeded Native Session C
```

### 2. Data Model

All duration columns use `_ms` and count columns use `_count`.

- **`agent_conversations`:**
  - `summary` (`TEXT NULL`): agent-authored summary written via `record_session_minutes` (`conversation_summary`).
  - `closed_at_ms` (`INTEGER NULL`), `close_reason` (`TEXT NULL`: `'resolved' | 'cleaned' | 'superseded'`).
  - `reopened_from` (`TEXT NULL`): links a reopened Conversation to its source Conversation ID.
  - `runner`, `model`, `effort`, `account_id`: nullable **overrides** (`NULL` inherits from the persona; the legacy `DEFAULT 'agy'` was removed).
  - Exposes `native_session_id` (derived from the latest reported Native Session; the legacy `agy_conversation_id` column was removed).
  - Archiving via topic switch does not set `closed_at_ms` / `close_reason`; only explicit closure sets them.
- **`conversation_native_sessions`:**
  - `id` (PK), `conversation_id` (FK `agent_conversations.id`), `runner`, `model`, `account_id`, `native_session_id` (`NULL` until reported by the runner), `started_at_ms`, `ended_at_ms`, `end_reason` (`'exit' | 'runner_switch' | 'invalidated' | 'cleaned'`), `seeded_from_brief` (`INTEGER`, `1` if started from a Brief).
  - Opened by `launch_agent` before spawn (ended with `'exit'` if spawn fails) and by session restarts; ephemeral agents (initializer, flag resolvers) gain a row upon reporting a session ID. Closed when the next session opens (`'exit'`) or when the Conversation closes (`'runner_switch'` for `'superseded'`, `'cleaned'`), not on process exit.
- **`agent_chat_turns`:**
  - Includes `native_session_row_id` recording which Native Session produced each turn.
- **`agent_session_journal` (Minutes):**
  - Keyed to `conversation_id` (nullable for legacy pre-migration rows); `agy_conversation_id` retained only as a nullable native reference. (Note: `agent_session_metrics` and `snapshots` retain `agy_conversation_id` / native references alongside `conversation_id`.)
- **`conversation_search` (FTS5):**
  - Virtual FTS5 table holding one row per Conversation (`topic`, `summary`, plus Minutes `title`, `summary`, `decisions`, `tags`). Kept synchronized via `reindex_conversation` on conversation creation, summary update, and Minutes insert, and backfilled at startup if empty.

*Schema reset history:* `PRAGMA user_version` gated the initial transition (`CONVERSATION_SCHEMA_VERSION = 1`), backing up older DBs via `VACUUM INTO` (`oneship.pre-spec30-<epoch>.db`) before recreating conversation tables, while preserving `agent_session_journal` rows via the idempotent transactional migration `migrate_journal_to_conversation_key`.

### 3. Lifecycle

```text
open Conversation ──► Readiness Stub (synthetic turn, no model call)
        │               process spawned idle; nothing sent to the model
        ▼
first user message ──► prompt = [Persona Preamble] + [Brief if Reopen / hybrid resume] + user text
        │
        ▼
 working … (Resume on restart when runner unchanged)
        │
        ├─ runner switch ─► close Conversation (superseded), open a new clean one (no automatic Brief)
        ├─ clean context ─► close Conversation (cleaned), open a new one   ← most common closure
        └─ resolution ───► agent records Minutes + summary → close Conversation (resolved)
```

1. **Silent spawn & Readiness Stub:** Spawning starts the runner idle without sending a greeting prompt or burning a billable turn. The Thread receives a synthetic `system` turn (`"Agent ready"`).
2. **Persona Preamble delivery:** Stored in `ManagedProcess.pending_preamble` and prepended to the first `send_input` whenever `session_resume_id` is `None` (new Native Sessions or runners without native resume). Resumed sessions never re-receive it; persona edits take effect on the next non-resumed Native Session.
3. **Hybrid resume & runner switch:**
   - Opening the chat resumes the last active Conversation when the runner is unchanged and the Native Session is valid.
   - If a launch has no native session to resume (e.g., invalidated session) and the non-initializer Conversation already has turns, `launch_agent` builds the Conversation's Brief *before* spawning (`Persona Preamble + "---" + Brief` in `pending_preamble`, `seeded_from_brief = 1`). Build failure aborts the launch and closes the Native Session row.
   - Changing the runner via `apply_conversation_config` closes the active Conversation as `superseded` and creates a new clean Conversation (topic `"General Workspace"`) carrying the new overrides. Context from an earlier Conversation enters a new runner only via explicit **Reopen** or **Context Transfer**.
   - Clean context (`launch_agent` with `clean_context = true`) opens a new Conversation preserving current overrides.
4. **Thread separators:** Stream separators in the UI key on `conversation_id` and expose a `Reopen` action for closed Conversations above them.

### 4. The Brief (`src-tauri/src/brief.rs`)

A Brief is deterministic plain text assembled exclusively from SQLite without invoking any LLM:

- **Functions:** `compose_brief` (pure formatter/truncator) and `build_brief(conversation_id) -> Result<Brief, BriefError>`.
- **Contents (priority order):**
  1. **Header:** States explicitly that a Brief is *context*, not a replay (tool state and prior file reads are not reconstructed).
  2. **Summary:** `agent_conversations.summary` if present (authored by the agent in `record_session_minutes`).
  3. **Recent turns:** Last `supervisor.brief_recent_turns_count` (default `20`) turns; artifacts are referenced rather than embedded in full, and each turn receives an even share of the byte budget.
  4. **`BriefStateReport`:** Files touched (from snapshots/Minutes), technical-debt items, and TODOs created/resolved during the Conversation.
  5. **`BriefOpenItems`:** Pending approvals and unresolved delegations.
  6. **Minutes digest:** Decisions and tags from the Conversation's Minutes.
- **Byte budget & truncation:** Hard-capped at `supervisor.brief_max_bytes` (default `32768`) on valid UTF-8 boundaries. Over-budget drops proceed in reverse order: Minutes digest -> oldest turns -> summary truncation -> header truncation; the returned `Brief` lists `dropped_sections`.
- **Context transfer:** `ContextTransferModal.vue` calls `build_conversation_brief({ projectPath, agentId })`, previews the backend Brief, appends optional user notes, and sends it to the destination agent.

### 5. Configuration Precedence

For `runner`, `model`, `effort`, and `account_id` at launch (`conversation::apply_conversation_config`):

1. Explicit value in the launch request (chat selector choice).
2. Conversation override (non-`NULL` column on `agent_conversations`).
3. Persona declaration (`rula.toml`).
4. Project/global defaults, then runner schema baseline.

When a Conversation has no existing override and the selected value matches the persona declaration, no override is persisted so subsequent persona edits propagate immediately. For the `claude` runner, `account_id` is informational only because the CLI authenticates via its own login (`~/.claude/.credentials.json`).

### 6. Restoring Past Conversations (`search_conversations` & `reopen_conversation`)

- **Search:** `search_conversations(query, status?)` tokenizes user text via `fts_query_from_text` (quoting word by word and joining with `OR`), ranks by FTS5 relevance, scopes strictly to the caller's `project_id` and `agent_id`, and bounds results by `supervisor.search_conversations_max_results_count` (default `10`). An empty query returns an error (or recent entries depending on path—empty query is rejected in the tool/FTS parser). Turns themselves are not FTS-indexed; Conversations without a summary or Minutes match by `topic`.
- **Reopen:** `db_reopen_conversation` validates that the source Conversation belongs to the same project and agent and is not already active, closes the active Conversation as `cleaned`, creates a new active Conversation inheriting the source's `topic` and the *current* Conversation's overrides, and sets `reopened_from`.
- **Delivery:**
  - *MCP path (`reopen_conversation` tool):* Builds the source Brief and returns it directly in the tool response to the running agent.
  - *UI path (`reopen_conversation` daemon command):* If a live process is running, opens a seeded Native Session and queues the Brief via `queue_context_for_next_input` (delivered on the next user input after any pending Preamble). If stopped, `launch_agent` seeds via `reopened_from` while the reopened Conversation has zero turns of its own. *(Known limitation: once the reopened Conversation gains its own turns, subsequent restarts brief from itself rather than the source's summary.)*

### 7. Decisions & Open Items

- **Approved decisions (`D1`–`D8`, 2026-10-08):** Standardized Thread/Conversation/Native Session/Brief terminology; hybrid native Resume when runner unchanged; agent-authored summaries without hidden model calls; user/agent closure with skill-driven topic-change suggestions; clean Conversation on runner change (no automatic Brief across runners); synthetic `"Agent ready"` Readiness Stub; clean conversation schema reset on Phase B rollout.
- **Open items:**
  1. *Concurrent `agy` account isolation (audit F6):* Currently `launch_agent` writes to the single OS keyring slot (`service=gemini, username=antigravity`) under `keyring_lock()`. Verifying whether running `agy` instances retain independent startup credentials across token refreshes (vs. requiring a conflict guard or per-agent keyring isolation) remains open.
  2. *Snapshot `conversation_id` alignment (audit F11):* Milestone snapshots currently resolve native session IDs with fallback to Conversation IDs; full unification onto ONE-SHIP `conversation_id` remains open.

## Contracts

### Database Tables (`oneship.db`)

- `agent_conversations`: `id`, `project_id`, `agent_id`, `topic`, `status`, `summary`, `runner`, `model`, `effort`, `account_id`, `closed_at_ms`, `close_reason`, `reopened_from`, timestamps.
- `conversation_native_sessions`: `id`, `conversation_id`, `runner`, `model`, `account_id`, `native_session_id`, `started_at_ms`, `ended_at_ms`, `end_reason`, `seeded_from_brief`.
- `agent_chat_turns`: includes `native_session_row_id`, `approval_payload`.
- `agent_session_journal`: includes `conversation_id`, nullable `agy_conversation_id`.
- `conversation_search`: FTS5 virtual table (`topic`, `summary`, Minutes fields).

### Daemon Commands (`api::API_COMMANDS` / `daemonCall`)

| Command | Arguments | Returns | Description |
| :--- | :--- | :--- | :--- |
| `get_active_conversation` | `projectPath`, `agentId` | `AgentConversationRecord` | Returns or initializes active Conversation |
| `create_agent_conversation` | `projectPath`, `agentId`, `topic`, ... | `AgentConversationRecord` | Creates a new Conversation |
| `update_active_conversation_config` | `projectPath`, `agentId`, `runner?`, `model?`, `effort?`, `accountId?` | `AgentConversationRecord` | Applies precedence rules; runner switch closes as `superseded` |
| `get_agent_turns_continuous` | `projectPath`, `agentId`, ... | `AgentChatTurnRecord[]` | Streams turns across the Thread |
| `save_user_chat_turn` | `projectPath`, `agentId`, `conversationId`, `content`, ... | `AgentChatTurnRecord` | Persists user turn; rejects mismatched `conversationId` (`ConversationError::ConversationNotFound` / `ConversationMismatch`) |
| `build_conversation_brief` | `projectPath`, `agentId` | `Brief` | Builds Brief from active Conversation without model calls |
| `search_conversations` | `projectPath`, `agentId`, `query`, `status?` | `AgentConversationRecord[]` | Scoped FTS5 search bounded by `search_conversations_max_results_count` |
| `reopen_conversation` | `projectPath`, `agentId`, `sourceConversationId` | `ReopenOutcome` | Closes active as `cleaned`, opens reopened Conversation, delivers/queues Brief |

### MCP Tools (`src-tauri/src/mcp.rs`)

- `search_conversations(query, status?)`: Scoped to attested `CallerContext` (`project_id`, `agent_id`).
- `reopen_conversation(conversation_id)`: Validates ownership via `CallerContext`, reopens Conversation, returns Brief text.
- `record_session_minutes(..., conversation_summary?)`: Writes Minutes keyed to active `conversation_id` and updates `agent_conversations.summary`.

### Configuration Keys (`[plugins.supervisor]`, global-only)

- `supervisor.brief_recent_turns_count` (default `20`)
- `supervisor.brief_max_bytes` (default `32768`)
- `supervisor.search_conversations_max_results_count` (default `10`)

### Daemon Events

- `agent-conversation-turn-added`
- `conversation-topic-switched`

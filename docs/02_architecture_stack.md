# Architecture and Tech Stack

## Core Stack
ONE-SHIP implements a decoupled three-layer architecture tailored for single-machine **Linux workstations** (Arch/Omarchy on Hyprland as primary host, with multi-distro portability across Ubuntu, Fedora Workstation, and Linux Mint):

*   **Backend (`oneship-daemon`):** Rust (Tokio, Axum, `thiserror`, `ts-rs`, `rusb`, `serialport`). A persistent background daemon that is the **sole owner of child processes and storage engines**. It manages subprocess supervision, file watching, state hydration, hardware USB/serial probing, and continuous telemetry without memory leaks, broadcasting real-time events via `tokio::sync::broadcast`.
*   **Tri-Database Embedded Storage Layer:**
    1.  **SQLite (`~/.config/one-ship/oneship.db`):** Relational state in WAL mode with `r2d2` connection pooling (`projects`, `agent_conversations`, `agent_chat_turns`, `agent_session_journal`, `project_todos`, `project_technical_debt`, `project_tasks`, `project_milestones`, `knowledge_edges`, `voice_sessions`, `supervised_processes`, `snapshots`, `accounts`, `system_logs`).
    2.  **DuckDB (`~/.config/one-ship/oneship_telemetry.duckdb`):** Embedded columnar analytics engine storing high-frequency process-tree CPU, RSS memory, thread, and disk I/O samples for every supervised service and task run ([Universal Telemetry & Profiling](specs/04-observability/02-universal-telemetry-and-profiling.md)).
    3.  **LanceDB (`~/.config/one-ship/vectors.lance/` + Local `BGE-M3` INT8 ONNX):** Embedded vector store and local 1024-dimensional embedding engine (`fastembed` / `ort`) combined with Tree-sitter AST chunking to power offline-first transversal semantic search (RAG) across source code, living specifications, session minutes, tasks, and technical debt ([Session Lifecycle, Database Devlog & Knowledge Graph](specs/04-observability/01-session-lifecycle-and-devlog-graph.md)).
*   **Agent & Service Orchestrator ([Native Process Supervisor](specs/02-agents/01-native-process-supervisor.md)):** Rust (`supervisor.rs`). Spawns services, tasks, and headless multi-turn agent runners in isolated process groups with bounded output ring buffers. Supported agent harnesses are strictly those installed and used on the workstation:
    *   **Antigravity (`agy`)** over `stream-json`
    *   **Claude Code (`claude`)** over `stream-json`
    *   **OpenCode (`opencode`)** over ACP, configured with **DeepSeek**
*   **MCP & Operator HTTP Bus ([Streamable HTTP MCP Daemon](specs/01-architecture/04-streamable-http-mcp-daemon.md) & [Daemon Operator API](specs/01-architecture/05-daemon-operator-api-and-lifecycle.md)):** Rust (Axum on port `8765`). Exposes PID-attested Model Context Protocol endpoints (`/mcp`, `/mcp/rea`, `/mcp/desigma`, `/mcp/pcbcraft`) to managed agent subprocesses, alongside the fail-closed operator RPC endpoint (`POST /api/v1/call/<command>`, attested via `/proc/<pid>/exe`) and the Server-Sent Events stream (`GET /api/events`) consumed by the GUI.
*   **Frontend (The Hub):** Tauri v2 + Vue 3 + TypeScript + Pinia + Tailwind CSS + **CodeMirror 6** (`AppCodeEditor.vue`). A thin, reactive GUI shell that invokes daemon commands via `daemonCall` (typed end-to-end with `ts-rs`) and subscribes to `/api/events` SSE. It opens no database and supervises no processes; closing or hiding the window to the tray leaves the daemon and all running agents/services untouched.

## Multidisciplinary Maker Subsystems (`src-tauri/src/kopeng/`)
The backend is organized around modular domain subsystems under `kopeng` (see [Plugin Architecture](specs/01-architecture/01-plugin-architecture.md)):
*   **Agent Personas, Skills & Snapshots:** Dynamic persona configuration (`persona.rs`), on-demand skill symlinking (`skill.rs`), and hidden Git ref snapshots (`snapshots.rs`, `refs/one-ship/snapshots/`).
*   **VCS & OSS Collaboration:** Local Git & branch management (`git.rs`), provider-neutral GitHub/GitLab Forge management (`forge/`, `github.rs`, `gitlab.rs`), and Kanban/Timeline/Milestones + Fork/Upstream OSS workflows (`project_mgmt.rs`, [Project Management & Milestones](specs/03-projects/07-project-management-and-milestones.md)).
*   **Electronics & Instrumentation Lab:** USB oscilloscope driver (`owon_vds1022.rs`), logic analyzer capture (`fx2lafw.rs` / `sigrok-cli`), and MCU firmware toolchains (`firmware.rs`, `toolchain.rs`, [Electronics Workstation](specs/06-hardware-and-cad/01-electronics-workstation-and-instrumentation.md)).
*   **CAD, PCB & UI Design Bridges:** Headless preview and MCP/CLI bridges for 3D CAD (`solidcraft.rs`, [CAD & PCB Integration](specs/06-hardware-and-cad/03-cad-and-pcb-integration.md)), EDA/PCB (`pcbcraft.rs`), and UI vector design (`desigma.rs` / `oneship-designer`, [One-Ship Designer](specs/06-hardware-and-cad/02-oneship-designer-integration.md)).
*   **Reverse Engineering Gateway:** Multi-project FIFO job queue and daemon lifecycle manager for `rea` (`rea.rs`, [REA Integration](specs/06-hardware-and-cad/04-rea-reverse-engineering-integration.md)).
*   **Voice & Capability Core:** Native Gemini Live dictation into focused text fields (`dictation.rs`, `audio_capture.rs`, `dictationStore.ts`) plus the global Push-to-Talk Gemini Live controller over PipeWire (`voice_controller.rs`, `voice_harness.rs`, `capabilities/`). See [Voice Specs](specs/05-voice/README.md).

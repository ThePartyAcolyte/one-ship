# Development Log: Project-First Lifecycle Devlog, Tasks & Tech Debt Decoupling

**Date:** 2026-10-26  
**Topic:** Decoupling Journal, Devlogs, Actionable Tasks and Technical Debt from Active Agent Focus  
**Domain:** Frontend Stores (`dialogueStore.ts`), Relational UI (`DevlogJournalView.vue`), Backend Event Dispatch (`mcp.rs`), Living Specs (`docs/specs/22_session_lifecycle_and_devlog_graph.md`)  

---

### 1. Context & Problem Statement
Previously, `DevlogJournalView.vue` and `dialogueStore.ts` coupled session journals (`agent_session_journal`) to the transient `activeAgentId` of the UI:
- When an agent was selected in the taskbar or chat overlay, `dialogueStore.selectAgent` called `fetchSessionJournals(resolvedPath, agentId)`.
- When mounting or refreshing `DevlogJournalView.vue`, it called `store.fetchSessionJournals(pPath, store.activeAgentId ?? undefined)`.
- The SQLite query restricted results via `WHERE project_id = ? AND agent_id = ?`, hiding minutes and milestones generated by any other agent (e.g. `lead-architect`, `backend`, `frontend`, `git`).
- In addition, event listeners for `todo-updated`, `tech-debt-updated`, and `SessionMinutesRecorded` attempted to resolve the project path via `this.resolveAgentProjectPath(this.activeAgentId)`, silently failing when no agent was active or open.
- The "Reopen Conversation" action on devlog entries threw errors if no agent was active, or attempted to reopen under the wrong agent identity instead of the journal entry's originating `agent_id`.

### 2. Architectural Changes Executed

#### A. Backend & Event Broadcasting (`src-tauri/src/mcp.rs`)
- In `execute_record_session_minutes`: Added broadcast of `SessionMinutesRecorded` via `sup.emit_event(...)` upon successful insertion into `agent_session_journal`. This ensures immediate reactive synchronization across workspaces.

#### B. Store Unification (`src/stores/dialogueStore.ts`)
- **Project-First Fetching:** Decoupled `fetchSessionJournals`, `fetchProjectTodos`, and `fetchProjectTechnicalDebt` from requiring an active agent. When resolving project paths, they prioritize explicit `projectPath`, then fallback to `coreStore.activeProject?.path`.
- **Global Lifecycle Invariant:** In `selectAgent`, removed the agent-scoped filter on `fetchSessionJournals(resolvedPath)`, preserving the full project history.
- **Dynamic Reopen Resolution:** Enhanced `reopenConversation(sourceConversationId, specificAgentId?, specificProjectPath?)` to automatically select and switch to the conversation's originating agent (`journal.agent_id`), disarm lingering steps, reload conversations, and open the chat overlay seamlessly.
- **Resilient Event Listeners:** Updated event handlers (`todo-updated`, `tech-debt-updated`, `SessionMinutesRecorded`) to resolve project path from `payload.project_path` or `coreStore.activeProject?.path` when no agent is active.

#### C. Relational UI & Optional Agent Facets (`DevlogJournalView.vue`)
- **Unrestricted Initial Load:** `refreshAll()` now loads the complete project history for devlogs, tasks, and technical debt without passing `activeAgentId`.
- **Optional Agent Filter Bar:**
  - Added `devlogAgentFilter` and `todoAgentFilter` (default: `'all'`).
  - Added computed properties `availableDevlogAgents` and `availableTodoAgents` dynamically collecting agents with recorded entries.
  - Rendered brutalist filter buttons (`all` + individual agents) allowing the developer to optionally scope down without sacrificing default project-wide observability.
- **Decoupled Reopening:** Passed `journal.agent_id` and `currentProject.path` to `store.reopenConversation(...)`, allowing conversation continuity from any devlog card regardless of active UI state.

#### D. Living Specification (`docs/specs/22_session_lifecycle_and_devlog_graph.md`)
- Updated Section 3.1 with the **Project-First Lifecycle Invariant (Zero Agent Coupling)** rule documenting that devlogs, tasks, and technical debt belong to the project as a whole.

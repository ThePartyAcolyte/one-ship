# Devlog: Quota Management & Context Telemetry Full-Stack Audit and Fix

**Date:** 2026-09-17  
**Topic:** Forensic Audit of Multi-Account Quota Tracking, Payload Schema Realignment, and Decoupled Context Observability

---

## 1. Forensic Audit & Root Cause Analysis

A full-stack audit of the quota management and statusline ingestion system revealed that `account_quotas` in SQLite was frozen at stale values (36 hours without updates), despite active Antigravity chat sessions.

### Root Causes Uncovered:
1. **Antigravity CLI Schema Mismatch:**
   - The initial ingestion hook expected `payload["quota"]["windows"]` as an array of objects.
   - Live Antigravity CLI actually emits `payload["quota"]` as a dictionary of named pool buckets:
     `"gemini-5h"`, `"gemini-weekly"`, `"3p-5h"`, `"3p-weekly"`.
   - Each bucket contains `remaining_fraction`, `reset_time` (RFC 3339 ISO), and `reset_in_seconds`.
   - Because `"windows"` was missing, `five_h_pct` and `weekly_pct` resolved to `None`, skipping database persistence entirely.
2. **Missing State File & Broken Rust Quota Sync:**
   - Rust's `sync_quota_from_statusline_file()` looked for `~/.local/state/wang-kapawu/agy-statusline.json`.
   - Neither the directory nor the file was generated by the statusline hook, causing `sync_quota_from_statusline_file()` to return `false` on every turn.
   - In `execute_post_agent_response` (`mcp.rs`), because `synced` was `false`, `AccountQuotaUpdated` was never emitted to the frontend.
3. **Claude Quota Burn during Account Kickstart:**
   - In `probe_account_quota()`, two separate headless prompts were executed: `gemini-3.8-flash-low` and `claude-sonnet-4-6`.
   - Inspection of Google's Code Assist API confirmed that any single call returns the complete quota summary for both Gemini and Third-Party pools. The secondary probe to Claude burned user Claude quota unnecessarily.
4. **Context Window vs Account Quota Scoping:**
   - `transcript.jsonl` contains per-turn token observability (`input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`) scoped strictly to conversation turns, but contains no account quota or reset epochs.
   - StatusLine payloads contain global account quota windows, but conversation context only applies when matched against active agent processes.

## 2. Implemented Solutions

### Track 1: Account-Level Quota Runway (`scripts/agy_statusline.py` & `kopeng/stats.rs`)
- **Multi-Pool Dictionary Parsing:**
  - Updated `scripts/agy_statusline.py` to parse both `gemini-5h` / `gemini-weekly` and `3p-5h` / `3p-weekly` atomically from `quota` dicts (with fallback to `windows` arrays).
  - Automatically calculates human countdowns (`Xh Ym` / `Xd Yh`) and Unix reset epochs (`now + reset_in_seconds`).
  - Upserts both `(account_id, "Agy", "gemini-pool")` and `(account_id, "Anthropic", "3p-pool")` in SQLite `account_quotas` simultaneously.
  - Resolves target account deterministically by authenticated email or active account fallback.
- **Atomic Local State Export:**
  - Atomically writes normalized snapshot to `~/.local/state/wang-kapawu/agy-statusline.json` via tempfile rename.
  - Implemented bounded diagnostic ring logger in `~/.local/state/wang-kapawu/statusline.log` (capped at 512KB).
- **Rust Engine Integration (`src-tauri/src/kopeng/stats.rs`):**
  - Added `parse_window_bucket()` and `parse_quota_records_from_value()` to parse multi-pool dictionaries directly in Rust.
  - Updated `sync_quota_from_statusline_file()` to load all pools and persist existing `warmup_enabled` preferences.
  - Streamlined `probe_account_quota()` to a single `gemini-3.8-flash-low` micro-probe, eliminating Claude quota depletion.

### Track 2: Conversation-Level Context & Token Observability (`src-tauri/src/mcp.rs`)
- In `execute_post_agent_response`, when an agent turn completes:
  - If `agy_conversation_id` is present, parses `transcript.jsonl` token metrics (`input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`) and updates `agent_session_metrics`.
  - Invokes `sync_quota_from_statusline_file()`.
  - Broadcasts `AccountQuotaUpdated` event to Tauri frontend and SSE/WS dialogue clients.

---

### Track 3: Chat Header Real-Time Token & Cache Observability (`ConversationPanel.vue` & `dialogueStore.ts`)
- **Conversation Token Resolution Cascade:**
  - Cascades resolution in `get_agent_metrics()`: direct Antigravity UUID -> `agent_chat_turns` SQLite record -> active supervisor process session -> most recent project turn.
  - Defaults `fetchActiveMetrics()` in `dialogueStore.ts` to automatically resolve current `activeAgentId`, `activeProjectPath`, and `activeConversationId` when called without arguments.
- **Real-Time UI Badges (`ConversationPanel.vue`):**
  - Added formatted token counts to header badges:
    - `Ctx: X% (Tk)` with dynamic color transitions: emerald ($\le 75\%$ of threshold), amber ($> 75\%$ of threshold), and pulsating rose ($> \text{threshold}$).
    - `Cache: X% (Tk)` displaying cache hit percentage and cached read token volume.
  - Multi-line brutalist hover cards via `AppTooltip` (`whitespace-pre-line break-words`) detailing exact total tokens, fresh input tokens, cache read tokens, and cache creation tokens.
  - Implemented 10-second polling interval (`metricsPollInterval`) plus immediate trigger on `activeConversationId` changes.
